# 03 歌曲分析

```bash
uv run --python 3.12 --with librosa --with faster-whisper --with numpy --with scipy --with opencc-python-reimplemented python tools/analyze_song.py $P [--bpm 140] [--lang zh] [--skip-asr]
```
首次会下载 Whisper large-v3（约 3 GB），整首歌识别在 M 系列 Mac 上约 3–6 分钟，可以放后台跑。重跑时加 `--skip-asr` 复用识别结果。

## 输出（`$P/analysis/`）
| 文件 | 内容 |
|---|---|
| `tempo.json` | `bpm`、`beat`（一拍秒数）、`offset`（第一拍）、`bar0`（第 0 小节线）、`phase`、`grid`（fixed/dynamic）、`beats`（变速歌的真实拍点表） |
| `grid.json` | 八分音符网格上每个点的底鼓 `kick` 和军鼓 `snare` 强度（0–1+）→ 引擎用它做冲击 |
| `asr.json` | Whisper 原始字级时间 |
| `lyrics.json` | 每行歌词：`text`、`t`（每个字/字母的出现时间）、`t0`、`t1`、`matched`（匹配率） |
| `sections.json` | 段落起止、吸附到小节线的时间 `bar_t0`、小节号 `bar_index`、能量；每秒能量 |
| `report.txt` | 人读的摘要 |

## 怎么读 report.txt
- **速度**：Suno 等电子编曲通常是严格恒速，相位漂移在 ±5 ms 以内。
- **⚠ 判定为变速歌**：真人演奏、古风、抒情歌拍子会快慢浮动。此时自动改用逐拍跟踪的真实拍点，`bar:N` / `beat:N` 写法照常用，引擎按真实拍点换算。
- **匹配率低的行**：时间靠前后插值，通常误差在半秒内。是关键卡点（比如“冲破！”）就到 `asr.json` 里找相近的字核对，必要时在分镜里用 `~0.2` 微调。
- **段落小节号**：分镜的切点优先用这些小节线。
- **能量骤降点**：候选的“静默/急停”位置。

## 原理与已知坑
- 速度：在起音包络上搜索使拍点能量最大的 (BPM, 相位)，比 librosa 的 beat_track 稳。《成为谁》里 beat_track 给的是 143.5，实际是 140.00。
- 估计结果可能差一倍或一半；如果人听着明显不对，用 `--bpm` 指定。
- 小节相位：取底鼓最强的那一拍当小节第一拍。电子说唱常见“歌词晚一拍进来”，这是正常的：**切镜落在小节线，歌词晚一拍砸入**。
- 歌词对齐用单调全局对齐（Needleman–Wunsch）：重复的副歌也不会错位；ASR 识别出、歌词里没写的段落（Suno 结尾常多唱几遍）会被当成空白跳过。
- Whisper 中文常输出繁体，脚本已转简体；同音字错没关系，对齐按字形容错。
