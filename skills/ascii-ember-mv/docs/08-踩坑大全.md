# 08 踩坑大全（实战记录，遇到新坑请往下补）

## 歌曲分析
- **librosa beat_track 的速度不可信**：《成为谁》给出 143.5，实际 140.00。用起音包络搜索 (BPM, 相位)，看相位漂移验证。
- **变速歌**（古风、抒情、真人演奏）固定网格会越卡越偏：漂移 > 25 ms 时改用逐拍跟踪的真实拍点（analyze_song.py 已自动处理）。
- **歌词全局 difflib 对齐会被重复副歌带偏** → 用单调全局对齐（NW）。
- **句末标点**取了下一个字的时间，导致“！”先于前面的字出现 → 标点取前一个字的时间（引擎已处理）。
- Whisper 中文输出繁体、年份数字读法不同：比对前先转简体。

## 画面
- **轮廓光剪影转字符只剩细线**，人物是空的 → 原图用实心灰阶“石版画”。
- **黑发、黑衣转字符后一片空白** → 生图时要求“深灰带高光”，渲染时 `levels: [.02, .5]`、`gamma: 1.6` 提亮暗部。
- **全身像推近会把头裁掉** → `fy` 0.2–0.3，推近幅度别超过 1.4。
- **3D 粒子默认太小，像灰尘** → 点大小已经放大 2.5 倍；汇聚目标 `size` 7–10。
- **汇聚前半秒是空屏**：起点散得太开 → 默认的 scatter 半径已经收拢。
- **反色闪（difference）会把橙色反成蓝色**，破坏单一强调色 → 入场闪白用 ink 色 3 帧衰减，军鼓只轻提亮。
- **中文字放进半宽字符格会挤在一起** → 中文字符网格用方格（`zoomSpark` 已处理）。
- **竖版顶部歌词和 HUD 重叠** → 竖版顶部歌词统一从 y=350 开始（引擎已处理）。
- 竖版 3D 镜头要单独拉远（引擎 `camV` 已处理），否则会越过顶部安全线。
- `ctx.arc` 半径不能为负；颜色必须是 `#hex`。

## 生图
- **一张图画 2×2 四格**，比分四次生成一致得多。
- `codex exec -i 参考图` 的 `-i` 会吞掉后面所有参数 → 提示词前加 `--`（gen_images.sh 已处理）。
- `codex exec` 会读标准输入，在 while-read 循环里会吃掉清单 → 接 `< /dev/null`（已处理）。
- bash 读 TSV 时连续两个 Tab 会被合并 → 空字段写 `-`（脚本会自动补）。

## 剪辑与交付
- **长渲染要分段、可续跑**（render.mjs 每 10 秒一段），拼接用 concat demuxer（不重编码）；不要用 filter 双 trim 拼长片，会爆内存。
- 画面流实际时长可能比计算值少 1–3 帧：混音时以 `ffprobe` 量到的画面时长为准，否则鸣谢打字声会错位。
- **单遍 loudnorm 不准**（差约 1 dB）→ 两遍（deliver.py 已处理）。
- 打字声加增益后峰值会冲过 0 dBFS → 混音前加 `alimiter`（已处理）。
- **剪辑版接缝处的残帧**：被剪掉的镜头开头 0.1–0.2 秒会闪出来 → 画面剪点和音频剪点分开设置。
- **zsh 的坑**：`$VAR:l` 会被当成“转小写”修饰符，`$D[s]` 会被当成数组下标 → 拼 ffmpeg filter 时变量一律写 `${VAR}`。
- ffmpeg 滤镜里的时长参数不接受 `.025`，必须写 `0.025`（recut.py 已处理）。
- 这台机器的 ffmpeg 可能没有 `drawtext` 滤镜 → 审片标注用 Pillow（audit.py）。
- 本机 `ls` 可能被替换成 eza → 脚本里用 `/bin/ls` 或 glob。
- Python 的 `hash()` 每次运行结果随机 → 需要可复现的随机用 `ord()` 或固定种子。

## 协作
- 印在画面上的名字、署名、拼写，动手前和用户逐字确认（ALSOP 还是 ALSOPS）。
- 用户只要求改某一个版本时，其他版本一律不动；改动范围说清楚。
- 删除文件 = 移到废纸篓，并告诉用户位置。

## 开源版本检查
- `doctor.sh` 需同时检查 npm 依赖与 Chromium；已有 `node_modules` 不代表浏览器已安装。Node.js 低于 20 时应直接报错。
- 变速歌的 `bar:` / `beat:` 在校验器和渲染器中必须都使用 `tempo.beats`，否则通过校验后实际镜头仍可能漂移。
