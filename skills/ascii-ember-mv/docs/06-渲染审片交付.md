# 06 渲染、审片、交付

## 渲染
```bash
node engine/render.mjs $P stills --times 40.5,62.1 [--w 1920 --h 1080]   # 指定时刻静帧 → $P/out/stills/
node engine/render.mjs $P shots [--at .3,.8] [--w 960 --h 540]           # 每个镜头取点出静帧 → $P/out/shots_WxH/
node engine/render.mjs $P video [--t0 0 --t1 end] --w 960 --h 540 --name sample   # → $P/out/sample_960x540.mp4（无声）
```
- 视频按 10 秒一段渲染，中断后重跑会跳过已完成的分段；改了分镜要删掉对应的 `_parts` 目录或整个重渲。
- 速度参考（M 系列 Mac）：540p 约 80–100 fps，1080p 约 25–40 fps。
- 竖版只要 `--w 1080 --h 1920`（或 540×960）：引擎按竖版设计坐标重新排版，不是裁横版。
- 页面报错会打印 `[页面错误]` / `⚠ 渲染中的错误`，必须修。

## 审片清单（关键帧、样片、成片各过一遍）
```bash
node engine/render.mjs $P shots --w 960 --h 540 && uv run --with pillow python tools/audit.py $P/out/shots_960x540 $P/out/审片_横.jpg
node engine/render.mjs $P shots --w 540 --h 960 && uv run --with pillow python tools/audit.py $P/out/shots_540x960 $P/out/审片_竖.jpg
```
1. **人看得清吗**：字符画人物的脸、手、动作一眼认得出；太暗就调 `levels`（如 `[.02, .5]`）或 `gamma` 1.6，换更亮的原图。
2. **脸没被裁**：全身像推近时 `fy` 调小（0.2–0.3）让取景偏上。
3. **歌词**：不压人物主体、不缺字、不先出标点；竖版顶部歌词不碰 HUD。
4. **3D**：汇聚目标够大、认得出；锁定前不是一片空屏（起点粒子别散太开）。
5. **竖版安全区**（蓝框）：文字、人脸、logo 在 x 80–950、y 280–1560 内；红线（y 260 / 1760）以外只放背景。
6. **节奏**：抽帧条看切点和动作（`ffmpeg -ss T -i x.mp4 -vf "fps=10,scale=240:-2,tile=8x1" -frames:v 1 strip.jpg`）。
7. **转场**：没有被剪掉镜头的残帧、没有意外黑场。

## 交付
```bash
python3 tools/deliver.py $P $P/out/final_1920x1080.mp4 <片名>_横版        # 整首
python3 tools/deliver.py $P $P/out/test_960x540.mp4 测试 --start 144.03   # 只渲染了片段时给起点
```
自动完成：
- 两遍 loudnorm（-14 LUFS / -1 dBTP，缓存到 `analysis/song_norm.wav`）
- 合轨（画面不重新编码）
- 按成片时间轴生成 `.srt`
- 打印时长、响度、峰值、黑场

## 交付前自检
- 响度 -14 ± 0.5 LUFS，峰值 ≤ -1 dBFS，无黑场（片尾故意的空屏除外）。
- 横版、竖版、剪辑版、鸣谢版的时长和内容都对。
- 抽 3 帧看画面上的文字（片名、署名、标语）一个字一个字核对。
- 告诉用户：文件位置、时长、规格、已知问题；中间产物（`$P/out/`）等用户确认后再清理（移到废纸篓）。
